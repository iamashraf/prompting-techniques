# ReAct: what running it actually showed

ReAct interleaves reasoning with real tool calls: Thought, Action,
Observation, repeated until a final answer. The one tool here is a
real calculator — `Action: calculate[expression]` gets evaluated by
actual Python, not generated by the model.

## The totals are correct by construction, not by luck

The model called the calculator exactly twice — once for financial
impact, once for revenue at risk — got back `4725000` and `9950000`
from real arithmetic, then wrote the final report using those exact
values. No regex extraction, no judge, no "it happened to be right
this time." It's categorically different from every other technique:
Zero-Shot through Structured Output all asked the model to *compute*
better in some way; ReAct just removes computation from the model's
job entirely. There's no version of this where the total is wrong,
short of the tool itself being broken.

The loop converged cleanly in 3 steps — two tool calls, then a final
answer — with no wasted turns and no attempt to skip the tool and
guess. The model correctly recognized when it needed the calculator
and waited for the real observation before continuing.

## The cost is different in kind, not just in size

Every other "more calls" technique (self-consistency's 5 samples,
chaining's 4 steps) pays in tokens and wall-clock time. ReAct pays in
that too, but also in something new: you have to actually write and
secure a tool. `calculate()` started as a tempting one-line `eval()`
and had to become a proper AST-walking allowlist (no names, no calls,
no exponentiation, a length cap) before it was safe to hand to a model
that can put anything it wants inside those brackets. That's
engineering work no prompt-only technique requires.

## Takeaway

Structured Output caught a wrong total after the fact, with three
lines of Python. ReAct prevents the wrong total from ever existing, by
handing the one operation the model keeps getting wrong to something
that can't get it wrong. That's a stronger guarantee than anything
else in this repo — at the cost of writing real code, not just a
better prompt.
